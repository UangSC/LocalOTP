# 浏览器同步与另一台设备拉取

LocalOTP 使用真实的 `chrome.storage.sync` 接口。开启浏览器账号同步后，Edge 由微软账号的同步服务传输，Chrome 由 Google 账号的同步服务传输。扩展没有自建云端服务，也没有用假数据模拟同步。

但**写入同步存储成功不等于已经上传到云端，或另一台设备已经收到**。浏览器未登录、关闭自身同步或离线时，同步存储可能仅在本机工作。浏览器决定网络传输时间，插件不能强制立即从服务器下载，也不能可靠判断用户是否登录云端账号。

## 两端操作

1. **源浏览器**：确认浏览器个人资料已登录，浏览器自身同步已开启；进入 LocalOTP“设置 → 同步与备份”，开启“浏览器同步”，点击“立即同步”。
2. **目标浏览器**：使用同一种浏览器登录同一账号，开启浏览器同步，安装相同扩展 ID 的 LocalOTP。首次打开先设置该设备自己的管理密码。
3. **目标插件**：同样开启“浏览器同步”，点击“立即同步”。浏览器已经送达的远端记录会与本地账号、分类及删除记录合并；之后远端变更到达会由后台自动合并。

“立即同步”会读取当前浏览器的同步存储副本，合并后写回本地和同步存储。因此可以同时拉取和推送；不需要另设一个“云端下载”按钮。

## 没有收到时

**旧的无 key 解压版首次切换到固定 ID 版时，要先导出备份，再加载新版并导入。不要先卸载旧版。** 本次 1.6.1 Release 已包含固定公钥，Windows Edge 与 macOS Edge 的 ID 均应为 `mjpifhendkddjgmoheglnfciammaipji`。后续保留该 key 更新即可，加载目录不再决定 ID。

1.6.1 的“同步诊断 → 只读检查”可显示本机和当前 ID 的同步缓存条数。缓存为 0 时不能证明旧账号从未存在，也不能证明云端永久丢失；需要核对原 ID。原 1.5.0 同步键布局与本版兼容，同一 ID 不需要格式迁移。

- **Edge ↔ Chrome 不互通**：两个浏览器使用不同账号体系。Windows Edge ↔ macOS Edge 可以使用同一微软账号；Chrome ↔ Chrome 使用同一 Google 账号。
- 核对两端扩展 ID。设置中的“另一台浏览器如何拉取？”显示本机 ID，也可在扩展管理页面查看。未包含本次固定 key 的旧包仍可能按路径生成 ID，请确保两端都使用本次 Release。
- 不同 ID 时，可以先用“导出备份 / 导入备份”迁移。本次固定的是 GitHub ZIP 解压加载的身份，没有发布到扩展商店，也不会自动替换用户当前安装或迁移数据。
- 检查浏览器是否在线、同步是否暂停，插件是否显示容量或写入错误。同步上限约为 100 KB、每条 8 KB、512 条记录（含分类与删除记录）。
- 页面中的“同步完成”证明本地合并及 API 操作成功，不是两台设备云端传输的回执。

## 同步范围与已验证边界

同步账号、分类及删除记录。管理密码、外观、短时免密设置和免密授权不上云；临时验证码输入也不参与同步。

账号密码与 OTP 密钥在本项目中没有额外端到端加密。已验证真实扩展后台和 `storage.sync`、多设备合并模型、错误恢复与重开加载；尚未使用两台登录同一账号的真实设备完成云端传输验收。
