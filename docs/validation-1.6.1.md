# 1.6.1 修复与验证

日期：2026-11-06。核心修复由真实工具栏弹窗复现确认，不再以普通扩展标签页代替全部弹窗测试。

## 置顶误报“未解锁”

1.6.0 后台强制要求 `MessageSender.documentId`。实际 Edge 工具栏 POPUP 的消息中可能缺少该字段，尽管 `runtime.getContexts` 能列出其文档；普通标签页的消息则包含它。旧测试通过普通标签页调用弹窗 HTML，因此漏掉这个差别。

首次设置密码还存在第二个问题：调用后台解锁后没有检查返回的 `ok`，导致后台拒绝时页面仍然进入账号界面。此时没有有效 proof，点击常驻小窗自然失败，而旧错误提示又没有区分授权拒绝和窗口 API 错误。

本版：

- 保留扩展 ID、协议、页面路径校验。缺少 documentId 时采用页面内随机 clientId 标识请求来源；标识本身不授予权限，仍须真实密码验证及后台 proof。
- 首次授权失败保持锁屏，不再进入账号区。
- 防止延迟到达的本次授权通知清除刚获得的 proof。
- 分别显示授权失效、上下文无效、会话存储失败与窗口创建失败。
- 按钮显示“常驻 / 置顶 / 取消”，明确两个阶段的实际作用。

## 跨版本同步与只读诊断

1.5.0 与 1.6.0 沿用 `acc:` / `cat:` / `tomb:` 等同步键布局，升级本身没有切换数据库格式。未设置固定 key 的解压加载扩展由加载路径确定 ID。卸载旧扩展后从新目录加载，会进入另一同步空间。

本版增加只读诊断，显示当前扩展 ID、本机账号数与当前浏览器同步缓存条数；0 条时明确提示空空间。完成本地同步存储合并仍不等于收到云端回执。

新增只读恢复器生成工具 `tools/build-recovery.mjs`，可在用户确认的旧加载路径重建旧 ID，读取和导出原空间。它不实例化业务 store，不调用同步写入或删除。恢复是否成功取决于旧数据是否仍存在并由浏览器送达，不能承诺卸载后的云端记录一定保留。

合计 311 项。实际用户重新加载修复版后，已确认常驻小窗可以正常打开。系统级置顶仍需在常驻小窗中再次点击，这是保留稳定宿主与浏览器用户手势的两阶段设计。

旧数据恢复、当前账号内容和浏览器缓存快照属于用户本机事件资料，不放入源码或发布包。初期故障修复保持原安装身份；后续按用户要求增加固定公钥，并在此次 1.6.1 Release 分发。固定 ID 为 `mjpifhendkddjgmoheglnfciammaipji`；从无 key 的旧安装切换时需要一次备份迁移。

- 以上仍不代替两台已登录同一微软账号设备的云端传输验收；README 要求只在 A 端导入，以 B 自动收到账号、A 收到 B 修改的备注为成功依据。
